# Проверка договоров контрагентов

Консольный помощник на Python: читает Word-договор, составляет предварительные
замечания в интересах покупателя / заказчика и отвечает на уточняющие вопросы.
Учебная часть выполнена по [плану урока Zerocoder](https://university.zerocoder.ru/pl/teach/control/lesson/view?id=345148516&editMode=0).

## Запуск в VS Code

Откройте папку проекта и терминал. Нужен Python 3.10+.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если окружение уже создано, повторно создавать его не нужно. В `.env` рядом
с `main.py` укажите `PROXYAPI_API_KEY`; образец — [.env.example](.env.example).

```powershell
# Помощник попросит путь к договору
.\.venv\Scripts\python.exe -X utf8 main.py
# Проверить конкретный договор и продолжить обсуждение
.\.venv\Scripts\python.exe -X utf8 main.py --file "C:\Папка\Договор.docx"
# Только чтение файла локально, без отправки в API
.\.venv\Scripts\python.exe -X utf8 main.py --file "C:\Папка\Договор.docx" --inspect
# Только первая проверка, без диалога
.\.venv\Scripts\python.exe -X utf8 main.py --file "C:\Папка\Договор.docx" --no-chat
```

Те же действия доступны через **Terminal → Run Task**. После первой проверки
появится `Ваш вопрос:`. Например: «Почему аванс под риском?», «Предложи правку
этого пункта», «Сделай формулировку короче».

`/exit` или `выход` завершает диалог. `/reset` очищает из контекста уточнения,
сохраняя договор и первую проверку. `/help` показывает команды. История на диске
при `/reset` не удаляется; после перезапуска программы начинается новая сессия.

Текст выбранного договора и контекст вопросов передаются через ProxyAPI.
Первая проверка и каждый уточняющий вопрос — отдельный платный API-запрос;
пустой ввод и команды API не вызывают. Автоматических повторов нет.

## Выполнение задания: шесть шагов

1. **Мини-задача:** предварительная проверка договора контрагента со стороны покупателя.
2. **Промпт:** [prompts.json](prompts.json) содержит `name`, `role`, `context`,
   `question`, `format`, `test_input`. Сообщения строятся по схеме
   **роль → контекст → задача → формат**.
3. **Первый запуск:** исходный промпт на вымышленном договоре № У-17. Фиксируются
   модель, температура, лимит, JSON Schema, полные сообщения и расход токенов.
4. **Одна итерация качества:** во второй версии уточняется **только роль**.
   Контекст, задача, формат, входной договор и параметры запросов одинаковы.
5. **Сравнение:** валидность исходного JSON, привязка действий к пунктам договора,
   число и длина примечаний. [Сохраненные результаты](contract_results/README.md)
   содержат реальные ответы и краткую содержательную оценку.
6. **Артефакт:** пользовательский `README.md` с действиями из итогового ответа;
   также создается ZIP проекта для сдачи.

```powershell
# Проверить конфигурацию без API
.\.venv\Scripts\python.exe -X utf8 main.py --dry-run
# Два платных запроса для сравнения
.\.venv\Scripts\python.exe -X utf8 main.py --compare
# Собрать код, тесты и последнее успешное учебное сравнение
.\.venv\Scripts\python.exe -X utf8 main.py --package
```

Каждое сравнение получает новую папку `contract_results/<время запуска>/`.
Там находятся `before.json`, `after.json`, полный `report.json`,
`comparison.md` и итоговый чек-лист `README.md`. Неуспешный запуск не затирает
предыдущий успешный. Краткие метрики сравнения рассчитываются из ответов;
содержательную оценку следует сверять при повторении эксперимента.

## Модель и формат

| Параметр | Значение |
| --- | --- |
| API | `https://api.proxyapi.ru/v1/chat/completions` |
| Модель | `anthropic/claude-haiku-4-5` |
| Temperature | `0.2` |
| Лимит ответа | `3000` токенов |
| Вывод | `json_schema`, `strict: true` |

Все ответы, включая уточнения, используют формат из задания:

```json
{ "title": "...", "steps": ["..."], "notes": ["..."] }
```

JSON проверяется непосредственно из ответа модели. Markdown-обертки не удаляются,
данные не исправляются. Лишние поля, неверные типы и нештатное завершение ответа
считаются ошибкой. Для учебного примера запрашивается 5–8 шагов; для реального
договора и уточнений допускается 1–8 пунктов без выдумывания дополнительных рисков.
`notes` содержит до трех тезисов, до 25 слов каждый.

## Архитектура и данные

| Файл | Ответственность |
| --- | --- |
| `main.py` | Единственная точка запуска, режимы CLI, проверка своего договора |
| `contract_core.py` | Общие настройки, промпты, один API-клиент, проверка JSON и запись результатов |
| `documents.py` | Локальное извлечение текста из DOCX/TXT/MD |
| `dialogue.py` | Контекст уточнений и команды диалога |
| `experiment.py` | Сравнение двух промптов и сборка ZIP по списку разрешенных файлов |
| `prompts.json` | Две учебные версии, промпт реального договора и промпт уточнений |
| `tests/` | Локальные проверки без внешних запросов |
| [REVIEW.md](REVIEW.md) | Найденные проблемы, исправления и результаты ревью |

В диалоге закреплены исходный договор и первая проверка. К ним добавляются до
10 последних успешных пар уточнений. Старые пары целиком исключаются при
превышении лимита контекста приложения — 180 000 символов. Это ограничение
символов, а не точный подсчет токенов. Ошибки API не попадают в успешную историю.

Поддерживаются `.docx`, `.txt`, `.md` в UTF-8; старый `.doc` нужно пересохранить
как `.docx`. Из Word читаются основной текст и таблицы. Изображения, сканы,
колонтитулы и вложенные файлы не анализируются. Автоматические номера Word могут
отсутствовать в извлеченном тексте; для ссылок добавляются метки `[Абзац N]`.

Личные результаты и переписка сохраняются в
`private_contract_results/<время запуска>/`. В отчет не копируется весь исходный
договор, но ответы могут содержать его цитаты. Эта папка, `contracts/` и `.env`
исключены из Git и ZIP. Для работы нужны только `requests` и `python-dotenv`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

Результат — предварительный анализ текста и предложения для согласования.
Он не подтверждает надежность контрагента и не заменяет юридическую экспертизу
конкретного договора.
